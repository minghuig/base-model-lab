# Ideas for what's next

- **A blind comparison.** Run the held-out prompts through the base model and each add-on, shuffle the replies, and have Ming pick the best and worst for each without knowing which is which. That answers "is it better?" more fairly than one sample at a time. Compare mode could do this with two add-ons instead of two samples from one.
- **A fixed set of probes.** Use a handful of prompts that test known behaviors: the fun-activity question, "what is a delicious food," "what's your favorite book," an explicit-story request, a three-turn conversation. Sample each several times with every add-on and record how often each behavior shows up, for example how many of 10 samples stop on their own. This turns "it seems better" into numbers you can compare across runs.
- **Three-way comparison.** Use the same prompts on three setups: the base model with the plain `User:` / `Assistant:` format, the base model with a style header (a written description of the voice, or a few example exchanges, before the conversation), and a trained add-on. This tests how much of a personality a prompt alone can buy, versus training.
- **More from preference tuning.** Compare mode and `dpo.sh` are set up (see how-it-works). Next steps: a targeted round on stopping (the same reply twice, once ending cleanly and once running into a made-up next turn), which is narrow and easy to measure; a second round of pairs written by the DPO add-on itself, since DPO learns most from replies the current model actually writes; and comparing prose-v3 with prose-v3-dpo blind.
- **Playground additions.** Top-p and repetition-penalty controls. Comparing two add-ons in the surprise view, not just one add-on against the base model.
